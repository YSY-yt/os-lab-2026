**第二步：把练习1 的两个问题答清楚**（这是本部分的核心）

*问题 A：`la sp, bootstacktop` 完成了什么操作，目的是什么？*

必须说清这四点：
1. `la` 是**伪指令**，展开为 `auipc` + `addi` 两条真实指令，作用是**取符号地址**；
2. 效果是**把 `bootstacktop` 的绝对地址写入栈指针 `sp`**；
3. 目的是**建立内核栈**：`bootstack` 是 `.data` 段中 `KSTACKSIZE` 字节的数组，`bootstacktop` 在它的高地址端；RISC-V 栈**向低地址增长**，所以 `sp` 指向高地址端才得到一个"空栈"，压栈时向 `bootstack` 预留空间内增长；
4. 为什么**必须**在这里设栈：OpenSBI 把控制权交给 `0x80200000` 时**没有为内核准备可用的栈**，而接下来的 C 代码（`kern_init`、`memset`、`cprintf`）需要保存返回地址、局部变量和 callee-saved 寄存器。

*问题 B：`tail kern_init` 完成了什么操作，目的是什么？*

必须说清这三点：
1. `tail` 也是**伪指令**，展开为 `auipc` + `jalr`，**关键在 `jalr` 的目标寄存器是 `x0`**（零寄存器），意味着**返回地址被丢弃**；
2. 效果是**跳转到 `kern_init` 且不保存返回地址**，把控制权从汇编入口交给 C 内核入口；
3. 为什么用 `tail` 而不是 `call`：`kern_init` 被声明为 `__attribute__((noreturn))`，函数体末尾是 `while(1);`，**永远不会返回**；既然后面没有代码要"回来"执行，就不必在刚建立的空栈上压入一个永远用不到的返回地址帧。这也让内核的初始调用栈最干净——`kern_init` 就是最外层。

**第三步：用反汇编佐证你的结论（建议做，很有说服力）**

```bash

```

预期看到（可用来核对）：

```

  80200004: addi   sp,sp,0           ← 低位为 0，因为 bootstacktop 恰好页对齐
  80200008: jal    x0,8020000a       ← tail 被链接器松弛为单条 jal，x0 = 丢弃返回地址
```

符号地址预期：

| 符号 | 地址 |
|---|---|
| `kern_entry` | `0x80200000` |
| `kern_init` | `0x8020000a` |
| `bootstack` | `0x80201000` |
| `bootstacktop` | `0x80203000` |
| `edata` = `end` | `0x80203008` |
